# Form Extension Trait Pattern

Use this skill when working with a mixin-style RE type that is embedded into child
types through `inherit!(Child => Mixin, field)` and you want child types to access
the mixin's methods ergonomically.

This pattern exists because child types do not directly own the mixin's methods in
their own `impl` blocks. Instead, `inherit!` gives them `AsRef<Mixin>` / `AsMut<Mixin>`,
and the Extension Trait exposes the mixin API on all compatible child types.

---

## When to apply

Apply this pattern when ALL of the following are true:

- The file defines an RE struct used as a mixin in child types
- Child types inherit it with `inherit!(Child => Mixin, field)`
- The mixin exposes methods that child types should be able to call ergonomically
- The file does not already define `pub trait <MixinName>Ext`

Typical examples:
- `TESFullName`
- `BGSKeywordForm`
- `TESModel`
- any `BaseFormComponent`-style mixin reused inside larger RE structs

---

## Core rule

If a mixin method should be usable from a child type, expose it through:

1. methods on `impl Mixin`
2. `pub trait MixinExt`
3. blanket impl for all `T: AsRef<Mixin>` and, if needed, `AsMut<Mixin>`

Do NOT re-declare mixin methods directly on child types.

---

## Method inclusion rules

### Include ALL virtual methods

Every method generated by `virtual_method!` must be included in the Extension Trait.

Do not omit a raw virtual method just because a safe wrapper exists.

If both exist, include both.

Example:

    virtual_method! {
        pub const VFUNC_GET_FULL_NAME: usize = 0x05;
        pub fn get_full_name() -> *const core::ffi::c_char
    }

    #[inline]
    pub fn get_name_as_str(&self) -> &str {
        core_util::ptr_to_str(self.get_full_name())
    }

Then the trait must include both:

    fn get_full_name(&self) -> *const core::ffi::c_char;
    fn get_name_as_str(&self) -> &str;

Reason:
- raw virtual methods are still needed for engine interop / FFI
- safe wrappers are ergonomic helpers, not replacements

### Include useful non-virtual public helpers

If the mixin has useful public non-virtual methods that child types should also use,
include them in the Extension Trait.

Examples:
- `get_name_as_str`
- count/accessor helpers
- convenience predicates
- safe pointer conversion wrappers

Do NOT include:
- private helpers
- constructors like `ctor`
- internal-only relocation helpers
- methods not intended for child use

---

## Safe wrapper guidance

When a raw virtual method returns an unsafe or inconvenient type, prefer adding
a safe helper directly on `impl Mixin`.

Common examples:

### C string to `&str`

    #[inline]
    pub fn get_name_as_str(&self) -> &str {
        core_util::ptr_to_str(self.get_full_name())
    }

### Nullable pointer to `Option<&T>`

    #[inline]
    pub fn get_item(&self) -> Option<&ItemType> {
        unsafe {
            // SAFETY: engine returns either null or a valid pointer tied to `self`
            self.get_item_raw().as_ref()
        }
    }

### Nullable pointer to `Option<&mut T>`

    #[inline]
    pub fn get_item_mut(&mut self) -> Option<&mut ItemType> {
        unsafe {
            // SAFETY: engine returns either null or a valid unique pointer during this borrow
            self.get_item_raw().as_mut()
        }
    }

Rules:
- keep wrappers on `impl Mixin`
- mark them `#[inline]`
- add `// SAFETY:` comments where needed
- wrapper methods may also be included in the Extension Trait
- wrapper methods do not replace raw virtual methods

---

## `virtual_method!` rule

The current `virtual_method!` macro already injects `&self` internally.

Therefore declarations must look like this:

    virtual_method! {
        pub const DO_THING: usize = 0x04;
        pub fn do_thing(arg: *const ArgType) -> bool
    }

and NOT like this:

    virtual_method! {
        pub const DO_THING: usize = 0x04;
        pub fn do_thing(this: &MyMixin, arg: *const ArgType) -> bool
    }

Never write an explicit `this: &Mixin` parameter inside `virtual_method!`.

---

## Trait structure

Use this shape:

    pub trait MyMixinExt {
        fn get_raw_name(&self) -> *const core::ffi::c_char;
        fn get_name_as_str(&self) -> &str;
        fn get_count(&self) -> u32;
        fn set_name(&mut self, name: *const core::ffi::c_char);
    }

### Blanket impl

Use:
- `AsRef<Mixin>` for immutable methods
- `AsMut<Mixin>` for mutable methods

If the trait contains both immutable and mutable methods, use both bounds:

    impl<T: AsRef<MyMixin> + AsMut<MyMixin>> MyMixinExt for T {
        fn get_raw_name(&self) -> *const core::ffi::c_char {
            self.as_ref().get_raw_name()
        }

        fn get_name_as_str(&self) -> &str {
            self.as_ref().get_name_as_str()
        }

        fn get_count(&self) -> u32 {
            self.as_ref().get_count()
        }

        fn set_name(&mut self, name: *const core::ffi::c_char) {
            self.as_mut().set_name(name)
        }
    }

Unified rule:
- immutable call: `self.as_ref().method(args)`
- mutable call: `self.as_mut().method(args)`

Never manually pass `self.as_ref()` as a fake `this` argument.
The `virtual_method!` macro handles that internally.

---

## Placement rules

The Extension Trait belongs in the mixin's own file, not in the child file.

Correct:
- `tes_full_name.rs` contains both `TESFullName` and `TESFullNameExt`

Wrong:
- child file defines `TESFullNameExt`

The mixin module should be re-exported from `mod.rs`:

    pub mod tes_full_name;
    pub use tes_full_name::*;

This automatically re-exports both the struct and the trait.

---

## Child-type usage

If a child contains:

    inherit!(MyChild => MyMixin, mixin_field);

then `MyChild` should gain ergonomic access through the trait:

    let name = child.get_name_as_str();
    let raw = child.get_raw_name();
    let count = child.get_count();

No direct method duplication in the child impl is needed.

---

## Final checklist

Before finishing, verify all of the following:

- [ ] Every `virtual_method!` method is included in the trait
- [ ] Safe wrappers do not replace raw virtual methods
- [ ] Useful non-virtual helpers are included where appropriate
- [ ] Mutable methods use `AsMut`
- [ ] Immutable methods use `AsRef`
- [ ] No explicit `this: &Mixin` appears in `virtual_method!`
- [ ] Blanket impl uses `self.as_ref().method(...)` / `self.as_mut().method(...)`
- [ ] Child types do not re-declare mixin methods directly
